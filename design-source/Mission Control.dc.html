FLIGHT SYSTEMS — ARCHITECTURE & OPS

One stack, built to run itself

Four products, one deliberate architecture — chosen so a solo builder can operate like a team. Boring where it should be boring; clever only where it pays.

EDGE
Vercel

Zero-ops deploys, a preview URL for every change. Why: shipping speed beats infra novelty — I deploy daily without thinking about servers.

APP
Next.js + TypeScript

The same framework across all four products. Why: one mental model everywhere — anything learned on one product compounds across the fleet.

DATA
Supabase — Postgres + row-level security

Auth, storage, and RLS as the permission model — two users on Life Hub, whole tenants on the property platform. Why: permissions live in the database, not scattered through app code — fewer places to get security wrong.

AI
Claude — engine and pair-builder

The styling engine inside hatched; Claude Code across every build. Prompts are versioned in the repo and reviewed like code. Why: AI is a dependency to manage, not magic to sprinkle.

COMMS
Resend + scheduled jobs

Job Command Center reads pipeline state each morning and emails me the brief. Why: a tool you must remember to open is a tool you stop using.

HATCHED

Wardrobe images in Supabase storage; the styling prompt is the product's core IP — treated like source code.

JOB CMD CENTER

A scheduled job reads pipeline state each morning; Resend delivers the brief. The demo above mirrors that exact flow.

LIFE HUB

175k lines, 40 routes, one Postgres schema — RLS scoped to a two-person household.

PROPERTY

One deployment, N tenants: a config object per tenant, enforced by Postgres RLS.
